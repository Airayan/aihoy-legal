01 · Tech stack

02 · Autentikáció

Auth flow

Supabase Auth kezeli az összes hitelesítést. Az app egy AuthGate widget köré épül, ami az auth stream alapján router.

1

Belépés — email vagy Google OAuth

A Supabase Auth JWT tokent ad vissza. Google sign-in esetén a user.userMetadata['name'] mezőből kerül ki a full_name. RLS INSERT policy szükséges a profiles táblán — enélkül néma hibával sikertelen a regisztráció.

2

AuthGate — route döntés

AuthGate figyeli az onAuthStateChange stream-et. Ha van session → profil ellenőrzés (super_match_done mező). Ha false → Onboarding. Ha true → HomePage. Ha nincs profil (törölve) → LoginPage.

3

Onboarding — 4 lépéses profil setup

Szerepkör, utazási stílus, érdeklődési körök, korosztály + nyelv + nemzetiség. Mentés után super_match_done: true — az AuthGate ezután a főoldalra küld. A full_name auth metadatából szinkronizálódik ha a DB-ben még nincs.

4

Session kezelés

Session lejárat előtt 60 másodperccel az AuthGate automatikusan refresheli. Ha a refresh sikertelen → LoginPage. A FCM token törlődik kijelentkezéskor a profiles táblából.

RLS Policy gondolkodás

-- Példa: profiles tábla SELECT policy
-- Mindenki láthat profilokat (radar, match), de csak saját adatot módosíthat

CREATE POLICY "Profil olvasható" ON profiles
  FOR SELECT USING (true);

CREATE POLICY "Saját profil szerkeszthető" ON profiles
  FOR UPDATE USING (auth.uid() = id);

CREATE POLICY "Saját profil létrehozható" ON profiles
  FOR INSERT WITH CHECK (auth.uid() = id);

-- chat_messages: csak a booking résztvevői látják
CREATE POLICY "Chat üzenet olvasás" ON chat_messages
  FOR SELECT USING (
    booking_id IN (
      SELECT id FROM bookings
      WHERE user_id = auth.uid() OR organizer_id = auth.uid()
    )
  );

04 · Realtime

Chat és radar — realtime megvalósítás

A Supabase Realtime PostgreSQL változásokat stremel WebSocket-en. A Flutter app StreamBuilder helyett manuális StreamController-t használ — a StreamBuilder rebuild-onként új stream példányt hozna létre.

// Chat stream — StreamController pattern (nem StreamBuilder!)
Stream<List<Map<String, dynamic>>> getChatStream(String bookingId) {
  late StreamController controller;
  RealtimeChannel? channel;

  controller = StreamController(
    onListen: () async {
      await reload(); // kezdeti adat
      channel = _supabase
          .channel('chat_messages_$bookingId')
          .onPostgresChanges(
            event: PostgresChangeEvent.all,
            table: 'chat_messages',
            filter: PostgresChangeFilter(column: 'booking_id', value: bookingId),
            callback: (_) => reload(), // DB változáskor újratölt
          ).subscribe();
    },
    onCancel: () async {
      await channel?.unsubscribe();
    },
  );
  return controller.stream;
}

Radar jelenlét — user_presence tábla

A radar bekapcsolásakor user_presence upsert történik GPS koordinátákkal, lejárati idővel (expires_at), és match beállításokkal. A pg_cron 5 percenként törli a lejárt jelenléteket. A RadarStatus singleton szinkronban tartja a Flutter state-et DB nélkül is.

Olvasatlan üzenetek — per-user timestamp

organizer_last_read_at és user_last_read_at mezők a bookings táblában. Az unread számítás Dart oldalon történik: ha last_message_at > saját_last_read_at → olvasatlan. Így nincs szerver oldali számítás szükséges.

05 · Push értesítések

FCM V1 — Edge Function alapú küldés

A push küldés Supabase Edge Functionön keresztül megy, Service Account JSON alapú OAuth2 hitelesítéssel. A Flutter app nem hívja közvetlenül a FCM API-t.

1

FCM token tárolás

App indításkor a FirebaseMessaging.instance.getToken() lekéri a device tokent, ami a profiles.fcm_token mezőbe kerül. Kijelentkezéskor nullázódik. Reinstall után auto-refresh szükséges (backlog).

2

Edge Function: send-notification

Deno/TypeScript. Bemenete: token, title, body, data. A function a Supabase Vault-ban tárolt Service Account JSON-ból generál rövid életű Google OAuth2 tokent, majd POST-ol a fcm.googleapis.com/v1/projects/.../messages:send végpontra.

3

Foreground suppression

Ha az app előtérben van (WidgetsBindingObserver + NotificationService.isAppInForeground), a push értesítő nem jelenik meg — csak a badge számláló növekszik. A NotificationService.onNotificationTap callback kezeli a navigációt tapp esetén.

4

Edge Function: radar-match-notify

Radar bekapcsolásakor hívódik — megkeresi a kompatibilis, aktív jelenlétű usereket és push értesítőt küld nekik. Tartalmazza a feladó user_id-ját, amiből a fogadó appja közvetlenül a SuperMatch találatok oldalra navigál.

// Edge Function hívás Flutter oldalon
await _supabase.functions.invoke(
  'send-notification',
  body: {
    'token': fcmToken,
    'title': '💬 $senderName',
    'body': snippet,
    'data': {'type': 'chat_message', 'booking_id': bookingId},
  },
);

06 · Match kalkulátor

SuperMatch score logika

A RadarMatchCalculator.calculate() Dart oldalon fut — nincs szerver oldali számítás. A score 0–100% között mozog, 65% a hard floor.

A Smart 2-match algoritmus a 100%-tól lefelé 5%-os lépésekben keres, és megáll amint 2 találat van az adott küszöb felett. Ha csak 1 találat van 65% felett, azt adja vissza. 65% alatt senki nem jelenik meg.

Az AI intro generálás (Claude Haiku) az első 1-2 találathoz fut le — az Edge Function hangulat, szándék és Mood Fusion (pl. chill+party = "Laza bulis") alapján generál személyre szabott bemutatkozó szöveget.

07 · Edge Functions

Szerver oldali logika

Minden szerver oldali művelet Supabase Edge Functionön fut (Deno runtime). Nincs saját szerver, nincs VPS.

send-notification

FCM V1 push küldés. Service Account OAuth2 token generálás, Google FCM API hívás. Bemenete: token, title, body, data object.

radar-match-notify

Radar bekapcsoláskor keres kompatibilis aktív usereket, és push értesítőt küld nekik "valaki megtalált a radaron" üzenettel.

generate-match-intro

Claude Haiku hívás. Bemenete: két user neve, hangulat, szándék, score, Mood Fusion. Kimenete: rövid, humoros bemutatkozó szöveg. Nyelv detektálással.

delete-account

GDPR-kompatibilis fiók törlés. Törli: profil, trips, bookings, chat_messages, connection_requests, user_presence, storage avatár. Majd auth.admin.deleteUser().

08 · Amit szívesen megvizsgálnék

Nyitott kérdések — ahol vélemény kell

Ez egy solo projekt, AI asszisztenssel felépítve. Vannak döntések amikről nem biztos hogy a legjobb úton jártam — ezeket szívesen megvitatnám.

RLS policy lefedettség

Minden táblán van RLS, de nem biztos hogy minden edge case le van fedve. Különösen a bookings és chat_messages táblák aggasztanak — egy user láthat-e olyan chat üzenetet aminek nem résztvevője?

Realtime stream architektúra

A manuális StreamController + Supabase channel pattern működik, de kérdés hogy production terhelés esetén (100+ egyidejű user) hogyan skálázódik. Van-e jobb pattern?

GPS koordináta tárolás

A user_presence tábla plaintext lat/lng-t tárol. PostGIS extension nélkül a radius szűrés Dart oldalon (Haversine) történik. Ez skálázható megközelítés, vagy érdemes PostGIS-re váltani?

FCM token kezelés

A token reinstall után nem frissül automatikusan — ez backlog. A jelenlegi megoldás: app indításkor mindig újra lekérjük és frissítjük. Van-e elegánsabb megközelítés?

N+1 query probléma

Több helyen (pl. fetchMyTrips, fetchPendingBookings) a booking listán iterálva töltöm be a profilokat egyenként. Supabase-ben hogyan oldható meg ez elegánsan join nélkül?

Testing stratégia

Jelenleg nincs automatizált teszt — minden manuálisan tesztelve, Play Store belső beta tesztelőkkel. Egy Flutter/Supabase projekthez mi lenne a legpragmatikusabb testing megközelítés?
